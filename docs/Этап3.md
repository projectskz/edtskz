# Этап 3. Люди

Цель этапа (ТЗ п. 6): работа с людьми. Замещение, переадресация, контроль сроков с эскалацией и автовыполнением, автоматический запуск процессов, программируемые кнопки, процессы в формах объектов.

Код не проверялся платформой: ошибки загрузки, компиляции и выполнения ожидаются, их исправляем по списку. Сценарий проверки — [Тестирование.md](Тестирование.md), часть 3.

## 1. Что сделано

### Замещение (ФТ-304)

- **Документ «Замещение»** (раздел «Бизнес-процессы», список документов «Замещение»). Поля:
  - кто замещает и кого;
  - период («по» можно не заполнять — без срока);
  - какие задачи замещаются: все, по ролям или по схемам. Таблицы «Роли» и «Схемы» видны только при своей области;
  - основание, «Уведомить замещаемого»;
  - «По окончании вернуть задачи»: задачи, которые замещающий принял к исполнению, по окончании периода возвращаются замещаемому.
- Проверки при проведении:
  - нельзя замещать самого себя;
  - период задан правильно;
  - нет цикла (А замещает Б, Б замещает А), в том числе через цепочку.
- Замещение действует после проведения документа. Задачи **остаются у замещаемого** и дополнительно видны замещающему:
  - в «Моих задачах» появляется колонка «За кого», если есть чужие задачи;
  - в форме задачи в сводке пишется «вы замещаете: …».
- Замещающий выполняет задачу так же, как свою. В истории пишется «Петров (за Иванова)».
- Замещающий получает оповещения о задачах замещаемого. Замещаемому по флажку отправляется письмо о замещении.
- Цепочки замещения учитываются: если Б замещает А, а В замещает Б, то В видит задачи А.

### Переадресация (ФТ-309)

- На шаге-задаче есть флажок «Разрешена переадресация другому пользователю».
- В задаче появляется кнопка **«Переадресовать…»**: выбор пользователя и обязательный комментарий (если комментарий уже написан в задаче, он и используется). Задача передаётся новому исполнителю, в истории остаётся запись.
- Кнопку можно добавить на вкладке «Кнопки» с действием «Переадресовать» и своим заголовком. Если такой кнопки нет, а флажок стоит, добавляется системная.

### Контроль сроков (ФТ-308)

- На вкладке «Шаг» задачи есть группа **«Просрочка»**, поле «Если срок истёк»:
  - **Ничего** — только оповещение о просрочке (письмо «Задача просрочена»);
  - **Эскалация** — задача передаётся эскалационной роли шага; если её нет — эскалационной роли роли задачи; если и её нет — руководителю исполнителя;
  - **Автовыполнение** — через N дней после срока задача выполняется выбранной кнопкой (пусто — кнопкой по умолчанию). 0 дней — сразу по истечении срока.
- Проверка схемы: просрочка с эскалацией или автовыполнением без срока — ошибка.
- Срок отслеживается через очередь действий: запись ставится при создании задачи и снимается при выполнении. Регламентное задание «Контроль сроков» (15 мин) и «Обработка очереди действий» (1 мин) включаются при открытии конструктора.

### Автоматический запуск (ФТ-108)

- В конструкторе кнопка **«Правила запуска»**:
  - событие: **«При записи»** или **«При проведении»** объекта-предмета; **«По расписанию»** — для схем без предмета;
  - условие запуска на СКД — тот же редактор, что для линий (например, «Предмет.Сумма документа > 100 000»);
  - расписание — стандартный диалог расписания;
  - «Не запускать второй процесс по объекту, пока идёт первый»;
  - исключения: пользователи-авторы и значения реквизитов предмета, при которых процесс не запускается.
- Правила действуют для **опубликованной** схемы: при публикации и записи правил обновляется кэш.
- Запуск идёт не в транзакции записи объекта, а через очередь сразу после неё (фоновое задание). Ошибка в схеме не мешает записать документ, она пишется в журнал регистрации.
- Подписки на события: `кбп_ПриЗаписиОбъекта` (все документы и справочники) и `кбп_ПриПроведенииДокумента` (все документы). Для объектов без правил проверка — одно обращение к кэшу сеанса.

### Программируемые кнопки (ФТ-501, ФТ-502)

- На вкладке «Кнопки» новые колонки:
  - **«Действие»**: переход, завершить, вернуть, переадресовать, обработчик, **открыть форму**, **запустить процесс**, прервать;
  - «Форма / отчёт» — для «Открыть форму»: `Предмет` (карточка предмета) или полное имя формы (`Отчет.ВаловаяПрибыль` — основная форма, `Отчет.ВаловаяПрибыль.Форма.Настройки` — конкретная). Форма получает параметры `Предмет`, `Задача`, `Процесс`;
  - «Схема процесса» — для «Запустить процесс»: процесс запускается по этой схеме с тем же предметом, задача остаётся открытой;
  - «Видна, если» — текст условия видимости.
- Кнопка **«Условие видимости…»** под таблицей: условие на СКД по предмету и переменным процесса. Кнопка не показывается, если условие не выполнено.
- «Открыть форму», «Запустить процесс» и «Переадресовать» не выполняют задачу.

### Процессы в формах объектов

- Общая команда **«Процессы»** в панели навигации форм документов и справочников: процессы, в которых объект — предмет, и задачи текущего пользователя по нему.
- Общая команда **«Запустить процесс»** в командной панели форм документов и справочников: в выборе — только схемы для типа объекта; если схема одна, она подставляется сама.
- Формы типовых конфигураций не заимствуются. Команды видны пользователям с ролью «Использование процессов».

### Прочее

- «Мои задачи» при обновлении запускают обработку наступивших таймеров и продолжений процессов, не дожидаясь регламентного задания.
- Редактор условия принимает заголовок окна: «Условие перехода», «Кнопка … видна, если», «Условие запуска».
