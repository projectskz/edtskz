# Этап 4. Оповещения, администрирование, долги

Цель этапа (ТЗ п. 6): оповещения по шагам и шаг «Оповещение», панель администратора, отчёты, рассылки, миграция версий. Сначала закрыты долги этапов 2–3.

Код платформой не проверялся: ошибки загрузки, компиляции и выполнения ожидаются, исправляем их по списку. Сценарий проверки — [Тестирование.md](Тестирование.md), часть 4.

## 1. Долги этапов 2–3

### Доступность кнопок по условию (ФТ-204)

- В регистре кнопок шагов появился реквизит `УсловиеДоступности`.
- В конструкторе на вкладке «Кнопки»:
  - колонка «Доступна, если»;
  - кнопка **«Условие доступности…»** рядом с «Условием видимости…».
- В задаче кнопка с невыполненным условием видна, но недоступна. Во всплывающей подсказке написано, когда она станет доступна.
- Сервер перед выполнением проверяет и видимость, и доступность кнопки.
- Условие вычисляется при открытии задачи и по кнопке «Обновить».

### Поля к заполнению из реквизитов предмета (ФТ-403)

- На вкладке «Поля» есть колонка **«или реквизит предмета»**. Список выбора — реквизиты типа предмета схемы. Путь можно ввести и вручную.
- Правила для поля:
  - поле с одним именем (`Комментарий`, `Предмет.Сумма`) редактируется;
  - поле с путём через точку (`Контрагент.ИНН`) — только для просмотра;
  - если у пользователя нет права изменять предмет, поле тоже только для просмотра.
- При выполнении задачи изменённые значения записываются в предмет:
  - проведённый документ перепроводится;
  - в историю процесса пишется «Изменены реквизиты предмета: …».
- Обязательность проверяется так же, как у переменных.

### Производственный календарь (ФТ-406)

- Срок в единицах «Рабочие дни» и «Рабочие часы» считается по производственному календарю БСП «Календарные графики». Используется основной календарь конфигурации или календарь из настройки `ПроизводственныйКалендарь`.
- Рабочий день по умолчанию — с 9 до 18 часов (настройки `НачалоРабочегоДня`, `ОкончаниеРабочегоДня`).
- Если подсистемы нет или календарь не заполнен на нужный год, рабочими считаются будни. Предупреждение пишется в журнал регистрации.
- `кбп_АдаптерКонфигурации`: `ПроизводственныйКалендарь`, `ДобавитьРабочиеДни`, `ДобавитьРабочиеЧасы`, `ЭтоРабочийДень`.

### Множественный запуск вложенных процессов (ФТ-703)

- На шаге «Вложенный процесс» есть флажок **«Запустить по каждому элементу»** и группа настроек:
  - «По элементам» — откуда брать элементы:
    - `Товары.Подразделение` — разные значения колонки табличной части предмета;
    - `Переменные.Список` — элементы массива или списка значений из переменной.
  - «Элемент передать в переменную» — переменная вложенного процесса.
  - «Продолжить, когда завершились»: все, любая, N из M.
- Если элемент — ссылка типа предмета вложенной схемы, он становится предметом вложенного процесса. Иначе предмет наследуется от родителя.
- Когда нужное число процессов завершено, остальные прерываются. В их истории пишется «Не требуется…».
- Если элементов нет, шаг пропускается с записью в истории.
- Выходные переменные возвращаются от каждого завершившегося процесса. Значение последнего перезаписывает предыдущие.
- Проверка схемы: множественный запуск без «По элементам» — ошибка; режим «N из M» без N — тоже ошибка.

### Возврат в родителя (ФТ-707)

- На шаге-задаче есть флажок **«Можно вернуть и на шаг родительского процесса»**. Он работает вместе с «Разрешён возврат на доработку».
- В задаче вложенного процесса список шагов возврата дополняется пройденными шагами родителя с пометкой «(процесс «…»)».
- При возврате на шаг родителя:
  - вложенный процесс прерывается, вместе с ним — остальные процессы того же множественного запуска;
  - родитель возвращается на выбранный шаг;
  - запись пишется в историю обоих процессов.

## 2. Оповещения

### Кому и когда (ФТ-601, ФТ-604)

- В конструкторе вкладка **«Оповещения»**:
  - у шага-задачи — кого ещё оповестить о событиях задачи: назначена, выполнена, возврат на доработку, просрочена;
  - если ничего не выделено — оповещения **процесса целиком**: те же события для всех шагов, а также запуск, завершение и прерывание процесса.
- Колонки таблицы:
  - «Когда»;
  - «Кому» — исполнитель, автор, наблюдатели, роль, пользователь, пользователь из реквизита, произвольный адрес, обработчик;
  - «Кто именно» — тип значения подставляется по виду получателя. Для реквизита — путь от предмета (`Ответственный`, `Переменные.Контролёр`); если в реквизите строка с `@`, это адрес;
  - «Каналы» — пусто: как настроил получатель;
  - «Шаблон» — пусто: стандартный текст;
  - «Срочно» — не собирать в сводку; получатель не может отписаться.
- Стандартные оповещения работают и без настройки:
  - исполнителю и его заместителям — о назначении и просрочке задачи;
  - автору — о завершении и прерывании процесса.

  Если настроенная строка совпадает со стандартной (тот же получатель и канал), остаётся настроенная.
- Замещение учитывается для получателей «Исполнитель» и «Роль».
- Обработчик получателей получает в контексте массив `Получатели` и добавляет в него пользователей или адреса.
- Проверка схемы: строка без значения («Роль» без роли, «Адрес» без адреса и т. п.) — ошибка.

### Шаг «Оповещение»

- Элемент «Обработка» на схеме, «Вид шага» — **Оповещение**.
- «Шаблон оповещения» или «Текст оповещения» (тема — название шага). Получатели — на вкладке «Оповещения». Если получателей нет, оповещение уходит автору процесса.
- Шаг отправляет оповещение и сразу идёт дальше. В истории процесса пишется запись со списком получателей.
- Проверка: без шаблона и текста — ошибка.

### Шаблоны сообщений (ФТ-603)

- Справочник «Шаблоны сообщений», своя форма со списком параметров.
- Параметры:
  - готовые: `[Процесс]`, `[Схема]`, `[Автор]`, `[Предмет]`, `[Задача]`, `[Срок]`, `[Исполнитель]`, `[Инструкция]`, `[Комментарий]`, `[Результат]`, `[Ссылка]`;
  - реквизиты через точку: `[Предмет.Номер]`, `[Объект.Контрагент.ИНН]`, `[Задача.Срок]`, `[Процесс.ДатаСтарта]`;
  - переменные процесса: `[Переменные.Сумма]`.

  Даты выводятся с временем, булево — «Да»/«Нет». Неизвестный параметр остаётся в тексте как есть.
- Таблица «Другой текст для канала» задаёт отдельную тему и текст, например короткий текст для канала «В программе».
- Шаблон с заполненным «Для события» используется для стандартных оповещений этого события. Шаблон события «Дайджест» задаёт текст сводки (`[Количество]`, `[Список]`).

### Каналы и доставка (ФТ-606, ФТ-609)

- Каналы:
  - **«Интерфейс»** («В программе») — уведомления в «Моих задачах»;
  - **«Почта»** — через подсистему БСП.

  Внедренец добавляет свои каналы: `кбп_ПроцессыПереопределяемый.ПриРегистрацииКаналов` и `ПриОтправкеОповещения`.
- Каналы по умолчанию — настройка `КаналыПоУмолчанию` («Интерфейс, Почта»). Настройка `ОтправлятьПочту = Ложь` отключает только почту.
- Всё идёт через очередь `кбп_ОчередьОповещений`:
  - защита от дублей (событие + задача + получатель + канал + итерация);
  - 5 попыток с растущей задержкой.
- **«Мои задачи» → вкладка «Уведомления»:**
  - последние 100 уведомлений, непрочитанные — жирным, их число — в заголовке вкладки;
  - двойной щелчок открывает задачу или процесс;
  - пока форма открыта, новые уведомления раз в минуту всплывают справа внизу (больше трёх — одно общее).

### Личные настройки (ФТ-607, ФТ-608)

- «Мои задачи» → «Уведомления» → **«Настройки оповещений…»**:
  - каналы по умолчанию;
  - «Письма присылать»: сразу, раз в N минут, раз в день (в начале рабочего дня);
  - по каждому событию — «Получать» и свои каналы.
- Сводка собирает несрочные письма получателя в одно письмо. Срочные оповещения приходят сразу и не отключаются.

### Не вошло

- Событие «Срок скоро истекает», комментарии и упоминания.
- Каналы «Система взаимодействия», «Напоминания» и SMS — через адаптер, после проверки на конфигурациях.
- Условие на строке оповещения: хранится в регистре и учитывается, но в панели не редактируется.
- Всплывающие уведомления без открытых «Моих задач»: нужен модуль приложения расширения, проверим на платформе.
