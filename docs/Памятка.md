# Памятка разработчика (состояние и грабли)

## Где мы

- Этап 0 (прототип конструктора) проверен в базе, этап 1 (MVP) собран и загружается. Идёт прогон сценария `docs/Этап1.md` у пользователя. Ошибки исправляем по мере поступления.
- Ветка: `claude/friendly-hopper-nd0j4n`. PR не создаём без запроса.
- Пользователю отдаём **полный архив** `src/cfe` без `ConfigDumpInfo.xml`, с `Configuration.xml` в корне (python `zipfile`, UTF-8 имена). Он загружает его целиком в расширение `КонструкторБизнесПроцессов`.

## Как устроен код

| Что | Где |
|---|---|
| Метаданные (справочники, регистры, перечисления, роли) | `docs/СпецификацияМетаданных.md` → `python3 tools/gen/generate.py` → `build/cfe` (для частичной загрузки) |
| Формы и обработки | `tools/forms/build.py` (описание на Python) + `tools/forms/formlib.py` → сразу в `src/cfe` |
| Модули (общие и форм) | правятся прямо в `src/cfe/**/Module.bsl`, формат: UTF-8 с BOM, CRLF |
| Движок | `кбп_Движок` (запуск, задачи, выбор ветки, возврат, прерывание, журнал) |
| Кнопки и обработчики | `кбп_Действия`; адресация — `кбп_Адресация`; почта — `кбп_Оповещения` + `кбп_АдаптерКонфигурации` |
| Конструктор: синхронизация схемы, проверка, публикация, панель свойств | `кбп_КомпиляторСхем` |

`build.py <каталог .bsl>` дополнительно перезаписывает модули из каталога исходников. **Без аргумента** он пишет только XML форм. Модули сейчас правим в `src/cfe`, поэтому запускаем без аргумента.

## Проверки без платформы (скрипты в `tools/check`)

- **Порядок тегов форм.** Сравнение с 635 формами БСП (`SSL=<клон ssl_3_1> python3 tools/check/formcheck.py <Form.xml>`). Канонический порядок уже зашит в `formlib.ORDER`, и сборщик падает на неизвестном свойстве.
- **BSL (`python3 tools/check/bslcheck.py src/cfe`)** проверяет:
  - парность блоков;
  - существование и экспорт вызываемых методов наших модулей;
  - число аргументов;
  - обработчики событий, команд и оповещений;
  - `Элементы.X` против формы;
  - директивы компиляции;
  - имена процедур, совпадающие с ключевыми словами.
- **Метаданные.** Значения перечислений в коде сверяются с `Enums/*.xml`, поля в запросах — с реквизитами объектов.
- **Эталоны формата.** БСП `1c-syntax/ssl_3_1` (sparse-checkout в scratchpad/ssl). Имена стандартных команд ищем через `mcp__github__search_code`, у него лимит запросов.

## Грабли (уже наступили — не повторять)

1. `Новый X().Свойство` — ошибка компиляции. Сначала присвоить объект переменной.
2. **Ключевые слова нельзя давать процедурам**, в том числе обработчикам команд формы: `Прервать`, `Продолжить`, `Возврат`, `Выполнить`, `Новый` и т. д. Поэтому `ПрерватьПроцесс`, `ПродолжитьПроцесс`. Значение перечисления `кбп_ВидыДействий.Прервать` через точку допустимо.
3. Переменные с именами глобальных функций или модулей (`Строка`, `Пользователи`, `Параметры`) не использовать.
4. **`ExtendedPresentation`** есть только у метаданных форм обработок и отчётов. У форм справочников Конфигуратор его отвергает.
5. Колонки таблицы формы, привязанной к ТЧ объекта: `DataPath` = `Объект.ТЧ.Колонка`, а не `ТЧ.Колонка`.
6. Длина номера строки ТЧ — 5 при режиме совместимости ниже 8.3.27.
7. Формы задачи и процесса при создании нового элемента: `Отказ = Истина` с сообщением, а не исключение.
8. Палитра поля графической схемы задаётся стандартными командами `Form.Item.<Поле>.StandardCommand.InsertItem<Вид>`.
   - Подтверждены: `Start`, `Activity`, `Condition`, `Processing`, `Completion`, `Decoration`.
   - Команды для соединительной линии нет: линии тянутся мышью.
   - Для этапа 2 ещё не найдены имена команд для выбора варианта, разделения, слияния и вложенного процесса.
9. `ТекущийЭлемент` поля схемы недоступен в веб-клиенте. Там элемент выбирается в списке шагов справа.
10. Заимствованный `Справочник.Пользователи` сопоставляется по именам, один `.cfe` на все конфигурации. UUID в XML базы разработки: `fa1ef4b3-…`.

## Модель кнопок и веток (этап 1)

- **Кнопки шага:**
  - если настроены в `кбп_КнопкиШагов`, используются они;
  - если линий из задачи несколько и на них нет условий, каждая линия становится кнопкой с `ИдКнопки = ИдПерехода`;
  - иначе одна кнопка «Выполнено».

  При `РазрешенВозврат` добавляется системная кнопка «Вернуть на доработку» (`кбп_Возврат`).
- **Выбор ветки** выполняется в таком порядке:
  1. `ИдПерехода` кнопки;
  2. линия с `ИдПерехода` или `ИдКнопки` = нажатой кнопке;
  3. условие-обработчик;
  4. «По умолчанию».
- **Условие** получает `ИдКнопки` предыдущей задачи транзитом.
- **Режим «Каждому»:** шаг ждёт всех исполнителей. Кнопка вида «Опасная» завершает шаг сразу.
