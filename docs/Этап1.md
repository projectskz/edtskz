# Этап 1. MVP: процесс согласования «из коробки»

Цель этапа (ТЗ п. 6): конструктор (Старт, Задача, Условие, Завершение), исполнители, «Мои задачи», кнопки, возврат на доработку, комментарии, оповещения по почте, журнал.

Этап собран за один проход. Код не проверялся платформой: ошибки компиляции и выполнения ожидаются, их исправляем по списку.

## 1. Что сделано

### Формы

| Форма | Где | Что умеет |
|---|---|---|
| Конструктор схем (`кбп_КонструкторСхем`) | Бизнес-процессы → Конструктор схем процессов | Справа список шагов и линий и **панель свойств**. Шаг: инструкция, срок, «каждому / любому из», возврат на доработку. Исполнители — таблица. Кнопки — таблица. Линия: «по умолчанию», результат задачи, условие-обработчик. В шапке «Предмет процесса» — тип объектов, по которым запускается процесс. Кнопка «Запустить процесс». |
| Мои задачи (`кбп_МоиЗадачи`) | Бизнес-процессы → Мои задачи | Вкладка «Мои задачи»: активные задачи, просроченные показаны красным, есть флажок «показывать выполненные». Вкладка «Мои процессы»: запущенные мной процессы и у кого они сейчас. Команда «Запустить процесс…». |
| Запуск процесса | «Мои задачи» → «Запустить процесс…» или конструктор | Схема, предмет (тип берётся из схемы), комментарий |
| Задача (форма элемента `кбп_Задачи`) | двойной щелчок в «Моих задачах» | Процесс, предмет, срок, инструкция, **кнопки шага**, комментарий, «Принять к исполнению», лента истории и комментариев |
| Процесс (форма элемента `кбп_Процессы`) | из задачи или «Моих процессов» | Задачи процесса, история, комментарии, **схема с подсветкой** (пройденные шаги зелёные, текущие жёлтые), переменные, «Прервать процесс» |

Формы собирает `tools/forms/build.py` (описание форм на Python, порядок тегов сверен с формами БСП). Модули лежат в `src/cfe`.

### Движок (`кбп_Движок`)

- **Запуск:** версия берётся из «текущей опубликованной», предмет проверяется по типу из схемы. Учитывается «запрет второго экземпляра». Переменные заполняются значениями по умолчанию. Маркер ставится на Старт.
- **Шаги:** Старт, Задача, Условие, Обработка (зарегистрированный обработчик) и Завершение. Остальные типы дают понятную ошибку «со следующего этапа».
- **Выбор ветки** выполняется в таком порядке:
  1. линия кнопки;
  2. линия, у которой «Результат задачи» совпадает с нажатой кнопкой;
  3. условие-обработчик;
  4. «По умолчанию».

  У шага с одной линией эта линия выбирается сразу.
- **Кнопки задачи:**
  - если в свойствах шага настроены кнопки, используются они;
  - если кнопок нет, а линий из задачи несколько, **каждая линия становится кнопкой**, заголовок кнопки равен подписи линии;
  - если линия одна, показывается кнопка «Выполнено».

  При «Разрешён возврат» добавляется кнопка «Вернуть на доработку».
- **«Каждому» и «любому из»:**
  - «Каждому»: шаг ждёт всех исполнителей. Кнопка вида «Опасная» (например, «Отклонить») завершает шаг сразу, остальные задачи отменяются.
  - «Любому из»: первый выполнивший завершает шаг.
- **Возврат на доработку:** на любой пройденный шаг-задачу или на шаги из настройки «куда можно вернуть». Комментарий обязателен. Режим «после доработки — сразу на вернувший шаг» работает. Если на целевом шаге включено «при возврате — тому же исполнителю», задача уходит прежнему исполнителю.
- **Принять к исполнению:** задача переходит в состояние «В работе». Если на шаге включено «снимать задачу с остальных», задачи других исполнителей отменяются.
- **Прервать** может автор или администратор процессов.
- **Транзакции:** каждая операция — одна транзакция с блокировкой процесса. От зацикливания стоит защита: не больше 1000 автопереходов.
- **Журнал:** запуск, переходы, создание, принятие и выполнение задач, возвраты, комментарии, предупреждения, завершение.

### Адресация (`кбп_Адресация`)

Поддерживаются способы: Пользователь, Роль, Автор, Исполнитель предыдущего шага, Из реквизита и Обработчик.

- **Роль:** исполнители берутся из регистра «Исполнители ролей» по объектам адресации, вычисленным из путей. Если записей с объектами нет, используется запись роли «без объектов».
- **Из реквизита:** путь от предмета через точку или «Переменные.Имя». В реквизите может быть пользователь или физическое лицо.
- **Если исполнителей нет,** задача уходит администратору процессов (настройка) или автору, в журнал пишется предупреждение.

Руководитель и «выбирает предыдущий исполнитель» — этап 3.

### Оповещения (`кбп_Оповещения`)

- **События и получатели:**
  - «Задача назначена» — исполнителю;
  - «Процесс завершён» и «Процесс прерван» — автору.
- **Очередь:** сообщение ставится в `кбп_ОчередьОповещений` внутри транзакции. После фиксации запускается фоновое задание отправки. Повтор — регламентное задание «Обработка очереди оповещений».
- **Отправка:** через системную учётную запись БСП. Адрес берётся из контактной информации пользователя. Если адреса нет, запись отменяется с пояснением.
- **Надёжность:** повторы с растущей задержкой, до 5 попыток.
- **Шаблон:** если в «Шаблонах сообщений» есть шаблон для события, используется он. Поддерживаются параметры `[Задача]`, `[Процесс]`, `[Предмет]`, `[Срок]`, `[Инструкция]`, `[Ссылка]`, `[Автор]`, `[Схема]`.

### Прочее

- `кбп_ПроцессыAPI` — рабочие `ЗапуститьПроцесс`, `ВыполнитьДействие`, `ВернутьНаДоработку`, `ДобавитьКомментарий`, `ПрерватьПроцесс`, `АктивныеПроцессыПредмета`, `ЗадачиПользователя`, `СостояниеПроцесса`.
- Обработчики внедрения: `кбп_ПроцессыПереопределяемый.ПриРегистрацииОбработчиков` (формат и пример в комментарии). Справочник `кбп_ОбработчикиПроцессов` обновляется при открытии конструктора.
- Настройки (`кбп_ПроцессыСлужебный.Настройка`): `ОтправлятьПочту` (Истина), `АдминистраторПроцессов`.
- Проверка схемы:
  - у ветки «Да» Условия должно быть условие: результат задачи или обработчик;
  - линии из задачи без настроенных кнопок ошибкой больше не считаются, они становятся кнопками.
- Роли: право на «Мои задачи» у всех ролей, кроме «Разработки кода». Модули, которые вызывает API, доступны во внешнем соединении.

## 2. Как загрузить

Полная загрузка присланного архива (`src/cfe`) в расширение → «Обновить конфигурацию базы данных». Данные этапа 0 (схемы, версии, шаги) сохраняются.

Если при загрузке или компиляции будут ошибки, пришлите их **все одним списком**.

## 3. Сценарий проверки

Подготовка:
- у двух пользователей (например, Вы и «Согласующий») есть роль `кбп_ИспользованиеПроцессов`, у Вас ещё `кбп_ДизайнПроцессов`;
- для почты у пользователей указан e-mail и настроена системная учётная запись (необязательно, без неё письма получат статус «Отменено» или «Ошибка»).

1. **Конструктор.** Откройте схему «Тест» из этапа 0 (или создайте новую). Если версия опубликована, нажмите «Изменить схему». В шапке «Предмет процесса» выберите, например, «Документ: Заказ клиента» или оставьте пустым.
2. Нарисуйте: Старт → Действие «Согласовать» → две линии: на Действие «Доработать» с подписью «Отклонить» и на Завершение с подписью «Согласовать». «Доработать» → линия обратно в «Согласовать». Сохраните.
3. Щёлкните «Согласовать» в списке справа. Панель показывает вкладки «Шаг», «Исполнители», «Кнопки». На «Исполнителях» добавьте строку: способ «Пользователь», пользователь «Согласующий». На «Шаге» задайте срок 1 день и инструкцию, отметьте «Разрешён возврат». Нажмите «Записать свойства».
4. «Доработать»: исполнитель — способ «Автор».
5. «Проверить» → ошибок нет → «Опубликовать» → «Запустить процесс» → выберите предмет → «Запустить». Откроется карточка процесса: на вкладке «Схема» «Согласовать» подсвечен жёлтым.
6. Под «Согласующим»: «Мои задачи» → задача «Согласовать» → кнопки **«Согласовать», «Отклонить», «Вернуть на доработку»** (кнопки по линиям). Нажмите «Отклонить» с комментарием.
7. Под собой: в «Моих задачах» появилась «Доработать», выполните её («Выполнено»). Снова задача «Согласовать» у согласующего.
8. Согласующий: «Вернуть на доработку» → шаг «Доработать» (если пройденный шаг один, выбор не показывается) → комментарий. Задача вернулась автору, в ленте запись «Возврат на доработку».
9. Согласующий: «Согласовать» → процесс «Завершён», автору ушло письмо (или запись в «Очереди оповещений» с причиной).
10. **Условие.** Новая схема: Старт → «Согласовать» → Условие → линия на Завершение и линия на «Доработать».
    - Для «Согласовать» на вкладке «Кнопки» добавьте две кнопки: «Согласовать» (вид «Основная») и «Отклонить» (вид «Опасная»).
    - Линию Условия на Завершение выберите в списке и на вкладке «Линия» задайте «Результат задачи» = «Согласовать: Согласовать».
    - Другой линии Условия поставьте «По умолчанию».

    Прогоните процесс обеими кнопками.
11. **Каждому.** В «Согласовать» два исполнителя, «Назначить» = «Каждому». Процесс ждёт обоих. Если один нажмёт «Отклонить» (вид «Опасная»), шаг завершится сразу.
12. Прервите процесс из карточки процесса: задачи отменены, состояние «Прерван».
13. Веб-клиент: шаги 3, 5, 6. Свойства выбираются в списке справа: двойной щелчок по схеме в веб-клиенте не работает.

## 4. Что прислать

- Ошибки загрузки, компиляции и выполнения: номер шага сценария и текст.
- Текст «Структуры схемы» для Условия, если его ещё не присылали: команда осталась в конструкторе.
- Что неудобно в панели свойств.
- Выгрузку расширения после исправлений — для `src/cfe`.

## 5. Не входит в этап 1 (дальше по ТЗ)

- Разделение и слияние, выбор варианта, таймер, вложенные процессы, условия на СКД, поля к заполнению (этап 2).
- Замещение, переадресация, эскалация, правила автозапуска, панель процесса в формах объектов (этап 3).
- Настройка оповещений по шагам (`кбп_ОповещенияШагов`), канал «Интерфейс», дайджесты (этап 3–4).
- Ограничение доступа к чужим процессам (RLS, этап 3): сейчас прочитать задачу может любой с ролью, а выполнить — только назначенный или администратор.
