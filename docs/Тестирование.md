# Сквозной сценарий тестирования

Проверяются этапы 1–4. Шаги пронумерованы: если что-то не так, пришлите номер шага, текст ошибки или скриншот.

**Обозначения:**
- «Список справа» — список «Шаги и линии схемы» в конструкторе.
- «Панель» — «Свойства» под этим списком.
- После любых правок на панели нажимайте **«Записать свойства»**.

---

## 0. Подготовка

1. Загрузите присланный архив в расширение **целиком**: «Загрузить конфигурацию из файлов» → «Обновить конфигурацию базы данных».
2. Пользователи для проверки:
   - **Вы** — роли «Дизайн процессов» и «Использование процессов» (или полные права);
   - **Согласующий** — второй пользователь с ролью «Использование процессов».

   Если второго пользователя нет, везде назначайте себя: проверять можно одному.
3. Откройте **Бизнес-процессы → Конструктор схем процессов**. При открытии включаются регламентные задания для таймеров и почты.

---

## Часть 1. Простое согласование (этап 1)

### 1.1. Схема «Согласование договора»

4. В поле «Схема» создайте новую: «Согласование договора». Откроется «Черновик: Версия 1».
5. «Предмет процесса» — оставьте пустым (процесс без документа). Можно выбрать тип документа, тогда при запуске придётся указать документ.
6. Нарисуйте схему палитрой над полем:

   ```
   Старт → [Согласовать] ─→ Завершение
                  │
                  └─→ [Доработать] ─→ обратно в [Согласовать]
   ```

   - Кнопки палитры слева направо: Старт, Действие (задача), Условие, Выбор варианта, Разделение, Слияние, Обработка, Вложенный процесс, Завершение, Декорация.
   - Линию тянут мышью от края одного элемента к другому.
7. **«Сохранить»**. Справа появятся шаги и линии.
   - Названия задаются на панели: выберите шаг в списке → вкладка «Шаг» → «Название»: «Согласовать» и «Доработать».
   - Подписи линий: выберите линию → «Подпись»: «Согласовано» (в Завершение) и «Отклонить» (в «Доработать»).
   - После каждого изменения — «Записать свойства»: схема сохранится, и название появится на картинке.
8. Выберите линию «Доработать → Согласовать». На панели отметьте **«Это возврат»**. «Записать свойства».

### 1.2. Исполнители

9. Выберите «Согласовать» → вкладка **«Исполнители»** → «Добавить»: способ **«Пользователь»**, пользователь — **Согласующий**.
10. Вкладка **«Шаг»**:
    - «Инструкция исполнителю»: «Проверьте договор»;
    - «Срок»: 1, единица «Дни»;
    - отметьте «Разрешён возврат на доработку».

    «Записать свойства».
11. Выберите «Доработать» → «Исполнители» → способ **«Автор»**. «Записать свойства».
12. **«Проверить»**. Ожидается «Ошибок не найдено». Если ошибки есть, строки в списке помечены ⚠, а текст — внизу.
13. **«Опубликовать»** → **«Запустить процесс»** → «Запустить».

### 1.3. Прохождение

14. Откройте **Бизнес-процессы → Мои задачи** под Согласующим (или под собой, если назначили себя). Откройте задачу «Согласовать». Ожидается:
    - вверху сводка «Ожидает · осталось 23 ч»;
    - процесс, исполнитель, срок;
    - «Что сделать»: «Проверьте договор»;
    - кнопки **«Согласовано»**, **«Отклонить»**, «Вернуть на доработку» (кнопки созданы по подписям линий).
15. Напишите комментарий, нажмите **«Отклонить»**. Задача закроется.
16. Под собой: в «Моих задачах» задача «Доработать» → «Выполнено». Задача «Согласовать» снова у Согласующего.
17. Согласующий: **«Вернуть на доработку»** → комментарий. Задача вернулась вам («Доработать»), выполните её.
18. Согласующий: **«Согласовано»**. Процесс завершён.
19. Откройте процесс (из задачи ссылкой «Процесс» или «Мои задачи» → вкладка «Мои процессы»):
    - «Сейчас»: «Процесс завершён»;
    - вкладка «История»: весь путь;
    - вкладка «Схема»: пройденные шаги зелёные.

### 1.4. Прерывание

20. Запустите процесс ещё раз, откройте его карточку → **«Прервать процесс»** → причина. Задача «Согласовать» отменена, процесс «Прерван».

## Часть 2. Маршруты (этап 2)

### 2.1. Переменные схемы

21. В конструкторе откройте схему «Согласование договора» → **«Изменить схему»** (создаётся черновик версии 2).
22. **«Переменные схемы»** → «Создать»:
    - Название «Сумма договора» (имя заполнится само: `СуммаДоговора`), тип **Число**, по умолчанию 0. Записать и закрыть.
    - Название «Срочно», тип **Булево**, отметьте «Показывать в задаче». Записать и закрыть.

### 2.2. Поля к заполнению

23. Выберите «Согласовать» → вкладка **«Поля»** → «Добавить»: переменная «Сумма договора», отметьте «Обязательное». Ещё строка: «Срочно». «Записать свойства».

### 2.3. Условие на СКД

24. Перерисуйте схему:

    ```
    Старт → [Согласовать] → <Условие> ─→ [Утвердить у директора] → Завершение
                                    └─→ Завершение
    ```

    - Условие — ромб в палитре.
    - Линию «Согласовать → Доработать» можно удалить или оставить.
    - Подписи линий из Условия: «Больше миллиона» и «Остальное».
25. Задайте исполнителя шагу «Утвердить у директора»: способ «Автор» или пользователь. «Сохранить».
26. Выберите линию «Условие → Утвердить у директора» → **«Настроить условие…»**. В окне «Добавить» → поле **«Переменные процесса» → «Сумма договора»**, вид сравнения **«Больше»**, значение **1 000 000**. **ОК**. На панели появится текст условия.
27. Линия «Условие → Завершение»: отметьте **«По умолчанию»**. «Записать свойства».
28. «Проверить» → «Опубликовать» → «Запустить процесс».
29. В задаче «Согласовать» есть блок **«Заполните»** с полями «Сумма договора» (обязательное) и «Срочно».
    - Нажмите «Согласовано» с пустой суммой: ожидается сообщение «Заполните поле…».
    - Введите **2 000 000** → «Согласовано». Ожидается задача «Утвердить у директора». В карточке процесса на вкладке «Переменные» сумма 2 000 000.
30. Запустите ещё раз с суммой **500 000**: процесс сразу завершается.
31. *(Необязательно.)* Условие по предмету: выберите в шапке «Предмет процесса» тип документа, в условии — «Предмет» → раскройте реквизиты → например, «Сумма документа».

### 2.4. Параллельные ветки (Разделение и Слияние)

32. Новая схема «Параллельное согласование»:

    ```
    Старт → <Разделение> ─→ [Юрист]      ─→ <Слияние> → [Итог] → Завершение
                        └─→ [Бухгалтер]  ─┘
    ```

    Исполнители всех трёх задач — «Автор» (или разные пользователи). «Сохранить».
33. Выберите «Слияние». На панели «Продолжить, когда пришли»: **«Все ветки»**.
34. «Проверить»: ошибок нет. Для проверки валидации временно отсоедините одну ветку от Слияния и соедините её с Завершением → «Проверить». Ожидается ошибка «ветка разделения доходит до Завершения, минуя Слияние». Верните как было.
35. Опубликуйте и запустите. В «Моих задачах» **две задачи сразу**: «Юрист» и «Бухгалтер». В карточке процесса в блоке «Сейчас» — обе.
36. Выполните «Юрист». «Итог» ещё не появился. В истории запись «Ветка дошла до «Слияние»: 1 из 2».
37. Выполните «Бухгалтер». Появилась задача «Итог».
38. Режим **«Любая ветка»**: «Изменить схему» → Слияние → «Любая ветка» → опубликовать → запустить. Выполните одну из двух задач: вторая отменяется, появляется «Итог».
39. Возврат из ветки: у «Бухгалтер» отметьте «Разрешён возврат». В задаче «Бухгалтер» → «Вернуть на доработку». Предлагаются только шаги до разделения и этой ветки, шаги соседней ветки не предлагаются.

### 2.5. Выбор варианта

40. Новая схема «Выбор решения»:

    ```
    Старт → [Решение] → <Выбор варианта> ─ вариант «Одобрить»  → Завершение
                                          ─ вариант «Отклонить» → [Уведомить автора] → Завершение
                                          ─ вариант «Отложить»  → [Решение]  (линия «Это возврат»)
    ```

    - Варианты задаются в свойствах самого элемента на схеме: правой кнопкой по элементу → «Свойства» (стандартный диалог платформы).
    - Линии тянутся от конкретного варианта.
41. «Решение» → вкладка «Кнопки»: три кнопки **«Одобрить»** (Основная), **«Отклонить»** (Опасная), **«Отложить»**. «Записать свойства».
42. «Проверить»: ошибок нет, потому что названия вариантов совпадают с кнопками. Опубликуйте, запустите, проверьте все три кнопки.

### 2.6. Таймер

43. Новая схема «Напоминание»: `Старт → [Обработка] → [Задача «Проверить»] → Завершение`. Обработка — седьмая кнопка палитры.
44. Выберите «Обработка» → «Вид шага»: **Таймер** → «Ждать» 2 **минуты**. «Записать свойства». Задаче «Проверить» — исполнитель «Автор».
45. Опубликуйте и запустите. В карточке процесса «Сейчас»: «Таймер «Обработка» — ждёт до …». Задачи пока нет.
46. Подождите 2–3 минуты: регламентное задание запускает таймер, и задача «Проверить» появляется в «Моих задачах».
47. Если ждать не хочется или регламентные задания не работают (файловая база без запущенного клиента): карточка процесса → **«Не ждать таймер»**. Задача появится сразу.

### 2.7. Вложенный процесс

48. Схема **«Проверка контрагента»**:
    - `Старт → [Проверить контрагента] → Завершение`, исполнитель — «Автор».
    - Переменная «Результат проверки» (Строка), отметьте **«Выход»**.
    - Шагу «Проверить контрагента» — поле «Результат проверки» (обязательное).
    - Опубликуйте.
49. Схема «Договор с проверкой»:
    - `Старт → [Вложенный процесс] → [Подписать] → Завершение`. Вложенный процесс — последняя кнопка палитры перед Завершением.
    - Переменная «Результат проверки» (Строка), флажок «Показывать в задаче».
50. Выберите вложенный процесс: «Схема вложенного процесса» — «Проверка контрагента», режим **«Синхронно»**. Таблицу передачи оставьте пустой: одноимённые переменные передадутся сами. Исполнитель «Подписать» — «Автор».
51. «Проверить»: ошибок нет. Проверка рекурсии: вложите «Договор с проверкой» в саму себя — «Проверить» покажет ошибку «вызывает саму себя». Верните как было.
52. Опубликуйте и запустите. Ожидается:
    - в карточке процесса «Сейчас»: «Вложенный процесс …»;
    - вкладка «Вложенные процессы» — дерево;
    - в «Моих задачах» — задача дочернего процесса «Проверить контрагента».
53. Заполните «Результат проверки» = «Надёжный» → «Выполнено». Через несколько секунд (фоновое задание) появится «Подписать», и в блоке «Данные процесса» будет «Результат проверки: Надёжный». Если задача не появилась, нажмите в карточке родительского процесса «Не ждать таймер» или подождите минуту.
54. Прервите родительский процесс, пока идёт дочерний: дочерний тоже прерывается.

## Часть 3. Люди (этап 3)

Для этой части удобнее два пользователя: **Вы** и **Согласующий**. Схемы из части 2 не нужны.

### 3.1. Замещение

55. Под собой: раздел «Бизнес-процессы» → **«Замещение»** → «Создать»:
    - «Кто замещает» — **Вы**, «кого» — **Согласующий**;
    - «С» — сегодня, «по» — пусто;
    - «Какие задачи» — **Все**. Переключите на «По ролям» и «По схемам»: появляется своя таблица. Верните «Все».

    **«Провести и закрыть»**.
56. Проверка цикла: создайте второе замещение «Согласующий замещает Вас» → «Провести». Ожидается ошибка о цикле замещения. Закройте без записи.
57. Запустите «Согласование договора» (исполнитель «Согласовать» — Согласующий). В «Моих задачах» **под собой** задача «Согласовать» видна, колонка **«За кого»**: Согласующий.
58. Откройте задачу. В сводке «вы замещаете: Согласующий». Нажмите «Согласовано». В истории процесса: «Вы (за Согласующий)».
59. Распроведите или удалите замещение. Колонка «За кого» пропадает, чужие задачи больше не видны.

### 3.2. Переадресация

60. «Изменить схему» → «Согласовать» → вкладка «Шаг» → отметьте **«Разрешена переадресация другому пользователю»**. «Записать свойства», опубликуйте, запустите.
61. В задаче «Согласовать» есть кнопка **«Переадресовать…»**. Нажмите → выберите пользователя → введите причину. Задача ушла новому исполнителю, в истории — запись о переадресации с причиной.

### 3.3. Просрочка: эскалация и автовыполнение

62. Новая схема «Контроль срока»: `Старт → [Проверить] → Завершение`, исполнитель — **Согласующий** (или вы).
    - Вкладка «Шаг»: «Срок» **1**, единица **«Минуты»**.
    - Группа «Просрочка» → «Если срок истёк»: **«Автовыполнение»**, «Через, дней» **0**, «кнопкой» — пусто (кнопка по умолчанию).
    - «Проверить»: ошибок нет. Для проверки валидации очистите срок → «Проверить» → ошибка «просрочка без срока». Верните 1 минуту.
63. Опубликуйте и запустите. Через 1–2 минуты (регламентное задание) задача выполнена сама, процесс завершён. В истории — выполнение задачи автоматически.
    Если регламентные задания не работают, откройте «Мои задачи» → «Обновить»: наступившие действия запускаются при обновлении.
64. Эскалация: «Изменить схему» → «Если срок истёк»: **«Эскалация»**, «Эскалационная роль» — роль, в которой есть вы (или пусто — тогда руководитель исполнителя из типовой конфигурации). Опубликуйте, запустите. Через 1–2 минуты задача передаётся вам, приходит оповещение о просрочке.

### 3.4. Программируемые кнопки

65. «Изменить схему» у «Согласование договора» → «Согласовать» → вкладка «Кнопки» → добавьте строки:
    - «Открыть договор»: действие **«Открыть форму»**, «Форма / отчёт» — **`Предмет`** (нужен тип предмета в шапке схемы) или, например, `Отчет.<ИмяОтчета>`;
    - «Проверить контрагента»: действие **«Запустить процесс»**, «Схема процесса» — «Проверка контрагента» из шага 48;
    - «Срочно согласовать»: действие «Переход», линия — в Завершение.
66. Выберите строку «Срочно согласовать» → **«Условие видимости…»** → поле **«Автор»** **Равно** Согласующий → ОК. В колонке «Видна, если» — текст условия. «Записать свойства».
67. Опубликуйте, запустите:
    - «Открыть договор» открывает форму, задача остаётся открытой;
    - «Проверить контрагента» спрашивает подтверждение и запускает процесс, задача остаётся открытой;
    - «Срочно согласовать» не видна: процесс запустили вы, а не Согласующий. Если запустить процесс под Согласующим, кнопка видна.

### 3.5. Процессы в формах документов и автозапуск

68. Схема «Согласование документа»: в шапке «Предмет процесса» — тип документа вашей конфигурации (например, «Заказ клиента»). `Старт → [Согласовать документ] → Завершение`, исполнитель — «Автор». Опубликуйте.
69. Откройте любой документ этого типа:
    - в командной панели кнопка **«Запустить процесс»**: схема подставлена сама (она одна для этого типа), предмет заполнен → «Запустить»;
    - в панели навигации документа — **«Процессы»**: запущенный процесс и ваша задача по документу.
70. Автозапуск: в конструкторе «Согласование документа» → **«Правила запуска»** → «Добавить»: событие **«При проведении»**, «Активно». Колонка «Условие» → двойной клик (или кнопка «Условие…») → например, «Предмет» → «Сумма документа» **Больше** 1000 → ОК. Отметьте «Не запускать второй процесс по объекту, пока идёт первый». **«Записать и закрыть»**.
71. Проведите документ с суммой больше 1000. Через несколько секунд в «Моих задачах» — «Согласовать документ». Проведите ещё раз, не выполняя задачу: второй процесс не создаётся. Документ с суммой меньше 1000 процесс не запускает.
72. *(Необязательно.)* По расписанию: схема без предмета → «Правила запуска» → событие «По расписанию» → колонка «Расписание» → каждый день, каждые 5 минут. Процесс запускается регламентным заданием.

## Часть 4. Долги этапов 2–3 и этап 4

### 4.1. Кнопки, поля предмета, календарь

73. **Доступность кнопки.** «Изменить схему» у «Согласование договора» → «Согласовать» → «Кнопки» → строка «Проверить контрагента» → **«Условие доступности…»** → «Автор» **Равно** Согласующий → ОК. В колонке «Доступна, если» — текст условия. «Записать свойства», опубликуйте, запустите.
    - Кнопка «Проверить контрагента» **видна, но серая**. Подсказка при наведении: «Станет доступна, когда: …».
74. **Поле из реквизита предмета.** Схема «Согласование документа» (шаг 68) → «Изменить схему» → «Согласовать документ» → вкладка «Поля» → строка: «Переменная» пусто, **«или реквизит предмета»** — выберите из списка, например «Комментарий», «Обязательное». Ещё строка: реквизит `Контрагент.ИНН` (или другой путь через точку) — только просмотр.
75. Опубликуйте, запустите по документу. В задаче поле «Комментарий» с текущим значением из документа. Измените его → выполните задачу:
    - в документе комментарий изменился (проведённый документ перепроведён);
    - в истории процесса запись «Изменены реквизиты предмета: Комментарий»;
    - путь через точку показан только для просмотра.
76. **Рабочие дни.** Шаг с «Срок» **1**, единица **«Рабочие дни»**. Запустите в пятницу (или перед праздником): срок — следующий рабочий день по производственному календарю конфигурации. «Рабочие часы» считаются с 9:00 до 18:00 рабочих дней.

### 4.2. Вложенные процессы: множественный запуск и возврат в родителя

77. Схема **«Проверка позиции»**: предмет — тот же тип документа, что в шаге 68. Переменная **«Позиция»** (тип — номенклатура или «Строка»), отметка «Вход». `Старт → [Проверить позицию] → Завершение`, исполнитель — вы. На задаче — поле «Позиция» (только просмотр). **«Разрешён возврат на доработку»** и **«Можно вернуть и на шаг родительского процесса»**. Опубликуйте.
78. «Согласование документа» → «Изменить схему» → между «Согласовать документ» и Завершением вставьте **вложенный процесс** «Проверить позиции»: схема «Проверка позиции», режим «Синхронно».
    - Отметьте **«Запустить по каждому элементу»**. «По элементам» — `Товары.Номенклатура` (имя табличной части и колонки вашего документа). «Элемент передать в переменную» — «Позиция». «Продолжить, когда завершились» — **Все**.
    - «Проверить»: без «По элементам» — ошибка. Заполните, опубликуйте.
79. Запустите по документу с 2–3 разными позициями. После «Согласовать документ» в «Моих задачах» по задаче «Проверить позицию» на каждую позицию, в каждой — своя «Позиция». В истории родителя — «Запущено процессов: N». Выполните все: родитель завершается после последнего (в истории «Завершено вложенных процессов: N из N»).
    - Вариант: «Продолжить, когда завершились» — **Любая**. После первой выполненной задачи остальные процессы прерываются («Не требуется…»), родитель идёт дальше.
80. **Возврат в родителя.** Запустите ещё раз, в одной из задач «Проверить позицию» нажмите «Вернуть на доработку». В списке шагов есть «Согласовать документ (процесс «Согласование документа»)». Выберите его, укажите комментарий:
    - все вложенные процессы прерваны;
    - у родителя снова задача «Согласовать документ»; в истории родителя — «Возврат из вложенного процесса … на шаг …».

### 4.3. Оповещения

81. **Канал «В программе».** Откройте «Мои задачи» — появилась вкладка **«Уведомления»**. Запустите любой процесс с задачей себе. В течение минуты:
    - справа внизу всплывает «Новая задача: …»; щелчок открывает задачу;
    - на вкладке «Уведомления» — строка жирным, в заголовке вкладки — число непрочитанных;
    - двойной щелчок открывает задачу и снимает жирный шрифт. «Прочитать все» отмечает все.
82. **Личные настройки.** «Уведомления» → **«Настройки оповещений…»**:
    - список событий с флажком «Получать»; снимите «Задача назначена» → «Записать и закрыть». Новая задача больше не приходит ни в программу, ни письмом;
    - верните флажок. «Каналы по умолчанию» — «В программе»: письма перестают приходить, уведомления в программе остаются.
83. **Шаблон сообщения.** Раздел «Бизнес-процессы» → «Шаблоны сообщений» → «Создать»:
    - название «Согласовано», тема `Согласовано: [Предмет]`, текст `[Предмет.Номер] от [Предмет.Дата], сумма [Предмет.СуммаДокумента]. Комментарий: [Комментарий]` (реквизиты — вашего документа);
    - под текстом — список доступных параметров. «Записать и закрыть».
84. **Оповещения шага.** «Согласование документа» → «Изменить схему» → «Согласовать документ» → вкладка **«Оповещения»** → «Добавить»:
    - «Когда» — «Задача выполнена», «Кому» — **Автор процесса**, «Шаблон» — «Согласовано»;
    - ещё строка: «Кому» — **Пользователь**, «Кто именно» — выбор пользователя открывается сразу (тип подставлен по виду), «Каналы» — «В программе».
85. Ничего не выделяйте на схеме (щёлкните пустое место или «Перечитать») → на панели свойств вкладка **«Оповещения»** процесса целиком: «Когда» — «Процесс завершён», «Кому» — **Произвольный адрес**, «Кто именно» — ваш e-mail. «Записать свойства».
    - «Проверить»: строка «Кому — Роль» без роли даёт ошибку «не указано, кто именно».
86. Опубликуйте, запустите по документу, выполните задачу. Автор получает «Согласовано: …» с подставленными номером, датой и суммой; выбранный пользователь — уведомление в программе. После завершения на адрес приходит «Процесс завершён».
87. **Шаг «Оповещение».** Вставьте на схему элемент «Обработка», на панели свойств «Вид шага» — **Оповещение**:
    - «Шаблон оповещения» не выбирайте, «Текст оповещения» — `Документ [Предмет] согласован, сумма [Переменные.Сумма]` (имя вашей переменной);
    - вкладка «Оповещения»: пусто — оповещение получит автор процесса. «Проверить»: без шаблона и текста — ошибка.
    - При прохождении шага в истории процесса запись «Оповещение: получатели: …», процесс сразу идёт дальше.
88. *(Необязательно.)* **Сводка писем.** «Настройки оповещений» → «Письма присылать» — **Раз в N минут**, 10. Выполните несколько задач с оповещениями на почту: через 10 минут приходит одно письмо «Оповещения по процессам: N» со списком. Оповещения, отмеченные в схеме **«Срочно»**, приходят сразу.
