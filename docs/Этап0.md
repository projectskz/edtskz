# Этап 0. Прототип конструктора схем

Цель этапа (ТЗ п. 6): подтвердить, что графическая схема в пользовательском режиме сохраняется, загружается и разбирается в модель; проверить тонкий и веб-клиент на 8.3.27; зафиксировать режим совместимости и матрицу БСП.

## 1. Что сделано

| Объект | Назначение |
|---|---|
| Обработка `кбп_КонструкторСхем` (раздел «Бизнес-процессы») | Форма: выбор схемы и версии, поле `ГрафическаяСхема`, список шагов версии, результат проверки |
| `кбп_КомпиляторСхем` | Имена элементов, разбор схемы, синхронизация со справочником и регистром переходов, проверка (ФТ-105), черновик и копирование версии, публикация |
| `кбп_АдаптерКонфигурации.ТекущийПользователь()` | Автор и публикатор версии (БСП `Пользователи.ТекущийПользователь()`) |
| Роли `кбп_ДизайнПроцессов`, `кбп_АдминистрированиеПроцессов` | Право на обработку |

Команды формы:

| Команда | Что делает |
|---|---|
| Сохранить | Проставляет элементам схемы имена `ид<GUID>`, сохраняет картинку в версию, создаёт и обновляет элементы `кбп_ЭлементыСхем` и записи `кбп_ПереходыСхем`. Настройки существующих шагов и линий не теряются. Удалённый со схемы элемент помечается «Нет на схеме» и на удаление. |
| Проверить | Сохраняет и проверяет: один Старт, есть Завершение, входы и выходы, у Условия две ветки и одна «По умолчанию», у вариантов по одной линии, Разделение/Слияние ≥ 2 веток, у задач есть исполнители, достижимость от Старта и путь к Завершению. Шаги с ошибками отмечаются в списке. |
| Опубликовать | Проверка → статус «Опубликована», прежняя версия → «Архив», схема получает текущую версию. |
| Изменить схему | Черновик копированием опубликованной версии: элементы, переходы, кнопки, исполнители, оповещения, со ссылками на новые элементы. |
| Свойства элемента / двойной щелчок | Шаг → форма элемента `кбп_ЭлементыСхем`; линия → запись `кбп_ПереходыСхем`. Несохранённая схема сначала сохраняется. |
| Структура схемы | Диагностика: вид и свойства каждого элемента схемы, как их видит платформа. |

Шаг «Таймер» и «Оповещение» рисуются элементом «Обработка»; тип меняется в свойствах шага и при следующем сохранении не сбрасывается (Архитектура п. 5.1).

## 2. Как загрузить

Полная загрузка `src/cfe` (или присланного архива) в расширение `КонструкторБизнесПроцессов` → «Обновить конфигурацию базы данных». Данные не теряются: UUID существующих объектов не менялись. Затем выгрузить расширение обратно в `src/cfe` (п. 2.3 спецификации).

## 3. Сценарий проверки (тонкий клиент)

1. Бизнес-процессы → Конструктор схем процессов. В поле «Схема» создать схему «Тест» (кнопка создания в выпадающем списке).
2. Создаётся «Версия 1: Черновик». Нарисовать: Старт → Действие «Согласовать» → Условие «Согласовано?» → две линии: на Действие «Доработать» (которое возвращается в «Согласовать») и на Завершение.
3. **Сохранить.** В списке справа появились шаги. Выделить Условие → «Структура схемы»: пришлите текст целиком — по нему видно, как платформа отдаёт выходы Условия (есть ли у линий `НачалоВариант` и какого типа).
4. Двойной щелчок по «Согласовать» → открывается элемент справочника. Заполнить что-нибудь, записать, закрыть.
5. Двойной щелчок по линии от Условия к Завершению → запись перехода. Отметить «По умолчанию», записать.
6. **Проверить.** Ожидаемо: «не заданы исполнители» у задач. Добавить исполнителя через «Все функции → Регистр сведений Исполнители шагов» (Шаг = «Согласовать», способ адресации = Автор) — полноценная панель свойств будет на этапе 1. Повторить проверку.
7. Переименовать «Согласовать» на схеме, сохранить: элемент справочника тот же (настройки из п. 4 на месте), изменилось только наименование.
8. Скопировать элемент на схеме (Ctrl+C / Ctrl+V), сохранить: у копии новое имя, в справочнике — новый элемент.
9. Удалить со схемы «Доработать», сохранить: элемент помечен на удаление и «Нет на схеме». Отменить удаление (Ctrl+Z) и сохранить: пометка снята, настройки на месте.
10. **Опубликовать.** Статус «Опубликована», схема не редактируется. **Изменить схему** → «Версия 2: Черновик» с теми же шагами и настройками; в «Версии 1» ничего не изменилось.
11. Закрыть форму с несохранёнными изменениями — должен быть вопрос о сохранении.

## 4. Веб-клиент

Повторить шаги 1–3 и 10. Ожидаемо: схема рисуется и сохраняется; двойной щелчок по схеме показывает предупреждение, свойства открываются из списка шагов. Причина: в БСП (`КартаМаршрутаБизнесПроцесса`) текущий элемент графической схемы помечен как недоступный в веб-клиенте. Если в веб-клиенте недоступно и редактирование схемы — это главный риск этапа 0 (Архитектура п. 14): тогда в веб-клиенте конструктор открывается только на просмотр.

## 5. Что прислать по итогам

- Текст «Структуры схемы» из шага 3.
- Что не сработало в сценарии: номер шага и что произошло.
- Результат веб-клиента.
- Выгрузку расширения после проверки — для `src/cfe`.

## 6. Известные ограничения прототипа

- Свойства шагов и линий открываются в автоматических формах: видны все реквизиты, опубликованную версию платформа не запрещает править из этих форм. Своя панель свойств с запретом правки опубликованных версий — этап 1.
- Не проверяются парность Разделения и Слияния и рекурсия вложенных схем — этап 2.
- Ошибки проверки не подсвечиваются на самой схеме, только в списке шагов.
