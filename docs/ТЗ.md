# Техническое задание
## «Конструктор бизнес-процессов» — тиражируемое расширение для типовых конфигураций 1С

| | |
|---|---|
| Версия документа | 0.3 (учтены решения заказчика и анализ прототипа KPI 3.1) |
| Платформа | 1С:Предприятие **8.3.27** — основная; 8.5 — по остаточному принципу (см. 1.4) |
| Форма поставки | Расширение конфигурации (`.cfe`), назначение «Дополнение» |
| Целевые конфигурации | 1С:ERP, 1С:УНФ, 1С:УТ, 1С:Бухгалтерия предприятия, 1С:Комплексная автоматизация, 1С:Управление холдингом (минимальные релизы — в 1.4) |

## 1. Назначение и цели

### 1.1. Назначение
Продукт позволяет пользователям **в пользовательском режиме, без конфигуратора** описывать, запускать и контролировать бизнес-процессы: согласования, заявки, поручения, маршруты документов и т. п.

### 1.2. Цели
1. Бизнес-аналитик рисует маршрут процесса блок-схемой и публикует его без участия программиста.
2. Один и тот же дистрибутив устанавливается в любую из целевых конфигураций без доработки её объектов.
3. Прозрачность: для любого процесса видно, где он находится, кто за него отвечает, сколько длится каждый шаг и почему его вернули.

### 1.3. Что не входит в объём
- Замена платформенных объектов «БизнесПроцесс» и «Задача» в самих конфигурациях: продукт с ними не конфликтует и их не использует.
- Электронный документооборот с контрагентами, ЭП и юридически значимые согласования (могут подключаться позже через точки расширения).

**Отложено на этапы развития** (архитектура должна это допускать, но реализация — после основного функционала, см. раздел 6):

| Направление | Статус |
|---|---|
| Произвольный код в условиях и кнопках, визуальный конструктор цепочек действий | Следующие этапы (после MVP) |
| Лицензирование и защита | Следующие этапы |
| Работа в модели сервиса (1С:Фреш) | Не в MVP, возможно на развитии |
| Мобильный клиент (адаптивные формы в мобильном клиенте 1С) | Не на первом этапе; маркетинговое преимущество — в планах |
| Импорт маршрутов из платформенных бизнес-процессов конфигураций (согласования ERP, УХ) | Возможно на будущих этапах |
| Блок интеграций (1С:Документооборот, внешние системы, HTTP API) | После того как весь основной функционал работает стабильно |
| Платформа 8.5 | По остаточному принципу после 8.3.27 |

### 1.4. Минимальные поддерживаемые релизы

| Конфигурация | Минимальные релизы | Примечание |
|---|---|---|
| Бухгалтерия предприятия, ред. 3.0 | 3.0.206.19 | |
| Комплексная автоматизация, ред. 2 | 2.6.1.64; 2.5.27.88 | 2.5 — версия долгосрочной поддержки (ДП) |
| Управление нашей фирмой, ред. 3.0 | 3.0.14.143 | |
| Управление торговлей, ред. 11 | 11.6.1.64; 11.5.27.88 | 11.5 — ДП |
| 1С:ERP Управление предприятием 2 | 2.6.1.64; 2.5.27.88 | 2.5 — ДП |
| 1С:Управление холдингом | **не определён** | Нужно указать релиз, иначе УХ исключается из MVP |

Итого **8 эталонных баз** (без УХ) на платформе 8.3.27. На них проходят приёмочные тесты.

**Режим совместимости расширения** = минимальный из «Режимов совместимости расширений» перечисленных релизов. Он определяется на этапе 0 по эталонным базам (`Метаданные.РежимСовместимостиРасширенияКонфигурации`) и фиксируется в этом документе. Возможности платформы новее этого режима в продукте не используются.

**Две ветки ERP/КА/УТ (2.5 ДП и 2.6)** означают, что в них могут быть разные редакции БСП. Все различия закрываются адаптером (см. Архитектура, п. 3.2), дистрибутив один.

## 2. Термины

| Термин | Определение |
|---|---|
| **Схема процесса** (шаблон) | Описание маршрута: блок-схема, свойства шагов, условия, кнопки, оповещения. Имеет версии. |
| **Версия схемы** | Неизменяемый опубликованный снимок схемы. Запущенный процесс всегда работает по той версии, с которой стартовал. |
| **Экземпляр процесса** | Конкретный запуск схемы, обычно по объекту базы (документу, справочнику). |
| **Шаг** (узел) | Элемент блок-схемы: задача, условие, разделение, слияние, вложенный процесс, обработка, таймер, старт, завершение. |
| **Переход** | Стрелка между шагами, опционально с условием или привязкой к кнопке. |
| **Задача** | Поручение конкретному исполнителю, созданное на шаге «Задача». |
| **Роль исполнителя** | Бизнес-роль (например, «Финансовый контролёр»), через которую адресуются задачи. Это не роль прав доступа платформы. |
| **Объект адресации** | Уточнение роли: организация, подразделение, склад, проект и т. п. (например, «Финконтролёр **по организации ООО Альфа**»). |
| **Замещение** | Временная передача задач одного пользователя другому на период, целиком или по отдельным ролям. |
| **Возврат на доработку** | Переход процесса на один из предыдущих шагов с обязательным комментарием. |
| **Действие (кнопка)** | Настраиваемая кнопка на форме задачи или объекта, которая выполняет переход, обработчик или другое действие. |

## 3. Пользователи продукта

| Роль | Что делает |
|---|---|
| **Администратор процессов** | Настраивает продукт, роли исполнителей, каналы оповещений, права; управляет запущенными процессами (прервать, переназначить, перезапустить шаг). |
| **Методолог (дизайнер процессов)** | Рисует и публикует схемы, настраивает условия, кнопки, оповещения. |
| **Участник** | Получает задачи, выполняет их, пишет комментарии, возвращает на доработку, запускает процессы. |
| **Наблюдатель** | Видит ход процессов и отчёты в пределах своих прав, без права действий. |
| **Разработчик внедрения** | Регистрирует программные обработчики и кнопки через точки расширения (переопределяемые модули). |

Для каждой роли поставляется роль прав платформы с префиксом `кбп_`. Роли встраиваются в профили групп доступа БСП.

## 4. Функциональные требования

### 4.1. Графический конструктор схем (ФТ-1xx)

| № | Требование |
|---|---|
| ФТ-101 | Схема рисуется мышью в пользовательском режиме на поле графической схемы: добавить, переместить, соединить, удалить элемент, масштаб, выравнивание. |
| ФТ-102 | Типы элементов: **Старт**, **Задача**, **Условие** (да/нет), **Выбор варианта** (N веток), **Разделение** (параллельные ветки), **Слияние** (ожидание веток: все / любая / N из M), **Вложенный процесс**, **Обработка** (автоматическое действие без человека), **Таймер** (ожидание срока или даты), **Оповещение**, **Завершение**. |
| ФТ-103 | Свойства выбранного элемента редактируются на панели рядом со схемой: наименование, исполнители, срок, кнопки, условия, оповещения, поля для заполнения. |
| ФТ-104 | Схема привязывается к **типу объекта** базы (любой документ, справочник, бизнес-объект) или создаётся «без объекта» для свободных заявок. Список типов строится по метаданным текущей конфигурации. |
| ФТ-105 | **Проверка схемы** перед публикацией: ровно один Старт, достижимость всех шагов, каждая ветка ведёт к Завершению, у Условия заданы обе ветки, у Разделения есть парное Слияние, нет рекурсии вложенных процессов, для всех задач заданы исполнители. Ошибки подсвечиваются на схеме. |
| ФТ-106 | **Версионирование**: черновик → публикация. Опубликованная версия не редактируется. Правка создаёт новый черновик. Хранится история версий с автором и датой, можно сравнить две версии. |
| ФТ-107 | Копирование схемы, выгрузка и загрузка в файл (JSON), чтобы переносить схемы между базами (тест → прод, ERP → УТ). |
| ФТ-108 | **Правила запуска**: вручную из объекта или списка; автоматически при записи или проведении объекта (с условием); по расписанию; программно через API. **Исключения** из автозапуска (объекты, организации, пользователи). Запрет второго экземпляра процесса по тому же предмету (настройка схемы). |
| ФТ-109 | Параметры процесса: переменные процесса (тип, значение по умолчанию), которые заполняются на шагах и участвуют в условиях. |
| ФТ-110 | Режим «Просмотр» той же схемы для участников, с подсветкой пройденных, текущих и будущих шагов экземпляра. |

### 4.2. Условия (ФТ-2xx)

| № | Требование |
|---|---|
| ФТ-201 | **Конструктор условий без кода**: реквизит объекта или переменная процесса, вид сравнения, значение; группы «И», «ИЛИ», «НЕ»; доступ к реквизитам через точку (`Контрагент.ОсновнойМенеджер`). Реализуется на базе системы компоновки данных (СКД-отбор). |
| ФТ-202 | *(этап 6)* **Условие-выражение** на встроенном языке, выполняется в безопасном режиме (право «Разработка кода процессов»). |
| ФТ-203 | **Условие-обработчик**: выбор из списка программных обработчиков, зарегистрированных разработчиком внедрения. Рекомендуемый вариант для сложной логики. |
| ФТ-204 | Условия применимы к переходам, видимости и доступности кнопок, правилам запуска, отправке оповещений и адресации. |
| ФТ-205 | Кнопка «Проверить условие» на выбранном объекте прямо из конструктора. |

### 4.3. Ролевая модель и замещение (ФТ-3xx)

| № | Требование |
|---|---|
| ФТ-301 | Справочник **ролей исполнителей** с произвольным составом **объектов адресации** (0..2 измерения, например «Организация» и «Подразделение»). |
| ФТ-302 | Регистр **исполнителей ролей**: роль + объекты адресации → пользователи. Если исполнителей несколько, задача назначается «любому из» или «каждому» (настройка шага). |
| ФТ-303 | Способы адресации задачи: конкретный пользователь; роль (с объектами адресации из объекта или переменной процесса); автор процесса; исполнитель предыдущего шага; руководитель пользователя (через структуру предприятия / подразделения конфигурации, если есть); пользователь из реквизита объекта; программный обработчик. Вариант «исполнителя следующего шага выбирает исполнитель текущего шага» при выполнении задачи. |
| ФТ-304 | **Замещение**: замещаемый, замещающий, период, область действия (все роли / выбранные роли / выбранные схемы). Задачи на период замещения видны замещающему **и** остаются видны замещаемому. Замещение оформляется **документом** «Замещение» (проведение включает, отмена проведения снимает), что даёт аудит и основание. |
| ФТ-305 | Режимы замещения: «уведомлять замещаемого» и «переназначать задачи по окончании замещения обратно» (настраивается). |
| ФТ-306 | Цепочки замещений (А → Б → В) разрешаются до конечного исполнителя. Циклы запрещены при записи. |
| ФТ-307 | В задаче фиксируются **и назначенный, и фактический исполнитель** («Иванов за Петрова»). |
| ФТ-308 | **Эскалация**: при просрочке задача дублируется или переадресуется на эскалационную роль или руководителя. Действие при просрочке настраивается на шаге: ничего / эскалация / **автовыполнение** с результатом по умолчанию через N дней после срока. |
| ФТ-309 | Переадресация задачи вручную (с комментарием), если это разрешено на шаге. |
| ФТ-310 | Пустая роль (нет исполнителей) → задача уходит администратору процессов с пометкой, в журнале фиксируется предупреждение. |

### 4.4. Задачи и работа участника (ФТ-4xx)

| № | Требование |
|---|---|
| ФТ-401 | Рабочее место **«Мои задачи»**: мои, моих замещаемых, по ролям (свободные, «взять в работу»), просроченные, выполненные. Отборы, группировки, счётчик на начальной странице. |
| ФТ-402 | Форма задачи: предмет (ссылка на объект, открывается в один клик), описание шага, срок, история процесса, комментарии, вложения, карта процесса, кнопки действий. Информационная строка с выбранными переменными процесса (признак «показывать в задаче»). |
| ФТ-403 | Шаг может запросить **заполнение полей**: переменные процесса и реквизиты объекта, с обязательностью. |
| ФТ-404 | **Возврат на доработку**: на предыдущий шаг, на выбранный из пройденных, на автора. Комментарий обязателен. После доработки процесс возвращается на тот же шаг, который вернул (настройка «вернуть на вернувшего» или «пройти маршрут заново»). |
| ФТ-405 | **Комментарии**: лента комментариев по процессу и по задаче, упоминание пользователей (@), вложения (файлы через БСП «Присоединённые файлы», если есть, иначе своё хранилище). |
| ФТ-406 | Сроки: абсолютный, относительный (часы или дни), с учётом производственного календаря конфигурации (БСП «Календарные графики»), если он есть. |
| ФТ-407 | Групповое выполнение однотипных задач из списка. |
| ФТ-408 | Выполнение задачи из формы самого объекта: панель процесса встраивается в форму документа или справочника базы. |
| ФТ-409 | Встраивание кнопок в форму объекта **без правки формы**: панель процесса добавляется программно (подключаемые команды БСП), без заранее созданных групп в формах базовой конфигурации. |
| ФТ-410 | Настройка шага «при выполнении этого шага завершить шаг …» (снятие задач параллельной ветки). |
| ФТ-411 | **«Взять в работу».** В режиме «любому из» исполнитель принимает задачу к исполнению, после чего задачи остальных исполнителей шага снимаются. Текст кнопки принятия настраивается. |
| ФТ-412 | **Копии для сведения.** На шаге задаются получатели информационных копий задачи. Копия видна в списке задач, но без права выполнения. |
| ФТ-413 | Выбор исполнителя следующего шага и ветки маршрута в диалоге при выполнении задачи (если так настроен шаг). |
| ФТ-414 | В форме задачи доступны **отчёты**, заданные на шаге, с отбором по предмету процесса. |

| ФТ-606 | Отправка **асинхронная** через очередь: повторы при ошибке, журнал отправки, защита от дублей. Проведение задачи не ждёт отправки письма. |
| ФТ-607 | Пользователь может отписаться от необязательных оповещений и выбрать удобный канал. |
| ФТ-608 | **Группировка оповещений.** Пользователь или администратор задаёт способ доставки: сразу / раз в N минут / раз в день. Несрочные оповещения собираются в одно письмо-дайджест по шаблону. |
| ФТ-609 | Канал **«Интерфейс»**: оповещения внутри 1С (счётчик и всплывающие уведомления) без электронной почты. |

## 5. Нефункциональные требования

| № | Требование |
|---|---|
| НФ-01 | **Универсальность.** Одно расширение для всех 6 конфигураций. Заимствование объектов базовой конфигурации сведено к минимуму (см. Архитектура, п. 3). Обращения к подсистемам БСП выполняются только через адаптер, с проверкой наличия подсистемы. |
| НФ-02 | **Платформа.** Основная — 8.3.27, все этапы принимаются на ней. 8.5 — по остаточному принципу: тот же дистрибутив, отдельный прогон тестов, без возможностей, специфичных для 8.5. Режим совместимости расширения — по п. 1.4. |
| НФ-03 | **Клиенты.** Тонкий клиент и веб-клиент (актуальные браузеры); интерфейс «Такси»; работа без модальных окон и без синхронных вызовов. |
| НФ-04 | **Масштаб.** До 1 000 одновременных пользователей, до 100 000 активных экземпляров процессов, до 10 млн записей журнала. Открытие формы «Мои задачи» не дольше 2 с. Выполнение задачи (без обработчиков) не дольше 1 с. |
| НФ-05 | **Надёжность.** Изменение состояния процесса выполняется в одной транзакции с управляемыми блокировками. Повторное нажатие кнопки не создаёт дублей. Сбой обработчика не повреждает процесс: шаг помечается ошибочным, его можно повторить. |
| НФ-06 | **Безопасность.** Произвольный код выполняется только в безопасном режиме и только при наличии отдельного права. Доступ к экземплярам — через RLS: участник видит процессы, где он автор, исполнитель, замещающий или наблюдатель. Предмет процесса открывается с правами пользователя. |
| НФ-07 | **Модель сервиса** *(не в MVP)*. Работа в режиме разделения данных (1С:Фреш) для БП и УНФ — на этапах развития. Уже с MVP в коде нет решений, которые её исключают: регламентные задания и очереди вызываются через адаптер, нет обращений к файловой системе сервера. |
| НФ-08 | **Обновление.** Обновление расширения не требует снятия базовой конфигурации с поддержки. Обработчики обновления данных расширения версионируются. |
| НФ-09 | **Локализация.** Интерфейс на русском, архитектура допускает добавление языков. |
| НФ-10 | **Тестируемость.** Движок покрыт автотестами (Vanessa-ADD / YAxUnit) на эталонных схемах. Сценарные тесты запускаются на каждой целевой конфигурации. |

## 6. Этапы разработки

| Этап | Состав | Результат |
|---|---|---|
| **0. Прототип** | Графическая схема в пользовательском режиме: сохранить, загрузить, разобрать в модель. Проверка на 8.3.27 на 8 эталонных базах (п. 1.4), тонкий и веб-клиент. Определение режима совместимости расширения и матрицы различий БСП. | Подтверждена техническая реализуемость, зафиксирован режим совместимости. |
| **1. MVP** | Конструктор (Старт, Задача, Условие, Завершение), роли исполнителей, «Мои задачи», стандартные кнопки, возврат на доработку, комментарии, e-mail-оповещения, журнал. | Процесс согласования «из коробки» работает. |
| **2. Маршруты** | Разделение/слияние, выбор варианта, таймер, обработка, вложенные процессы, переменные процесса, конструктор условий на СКД. | Сложные маршруты. |
| **3. Люди** | Замещение, эскалация, переадресация, правила запуска, программируемые кнопки, встраивание в формы объектов. | Промышленная эксплуатация. |
| **4. Контроль** | Отчёты, панель администратора, миграция версий, рассылки по расписанию, прочие каналы. | Полнофункциональный продукт. |
| **5. Тиражирование** | Сертификация «1С:Совместимо», документация, демо-база, автотесты на всех конфигурациях. | Коробочный продукт. |
| **6. Расширенная настройка** | Произвольный код в условиях и кнопках (безопасный режим, отдельное право), визуальный конструктор цепочек действий, доп. обработки БСП как обработчики. | Сложная логика без программиста внедрения. |
| **7. Лицензирование** | Защита и лицензирование продукта (способ выбирается отдельно). | Коммерческая поставка. |
| **8. Развитие** *(приоритет уточняется)* | Платформа 8.5; модель сервиса (1С:Фреш); мобильный клиент; импорт маршрутов из платформенных БП; блок интеграций (1С:Документооборот, HTTP API, мессенджеры). | Расширение рынка. |

Этапы 6–8 начинаются, только когда функционал этапов 1–4 работает стабильно.

## 7. Принятые решения

| № | Вопрос | Решение |
|---|---|---|
| 1 | Минимальные релизы | Зафиксированы в п. 1.4 (кроме УХ). |
| 2 | 8.3.27 и 8.5 | Сначала 8.3.27; 8.5 — по остаточному принципу, тем же дистрибутивом. |
| 3 | Модель сервиса (Фреш) | Не в MVP, возможно на развитии (этап 8). |
| 4 | Мобильный клиент | Не на первом этапе; как маркетинговое преимущество — в планах (этап 8). |
| 5 | Произвольный код | Да, вместе с конструктором действий — на следующих этапах (этап 6). До этого — только зарегистрированные обработчики. |
| 6 | Лицензирование | На следующих этапах (этап 7). |
| 7 | Импорт маршрутов из платформенных БП | Не приоритет; предусмотреть на будущих этапах (этап 8). |
| 8 | Интеграция с 1С:Документооборот | Блок интеграций — после стабилизации основного функционала (этап 8). |
