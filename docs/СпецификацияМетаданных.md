# Спецификация метаданных расширения
## «Конструктор бизнес-процессов» (`КонструкторБизнесПроцессов`, префикс `кбп_`)

Документ фиксирует **состав объектов метаданных** расширения: имена, типы реквизитов, измерения регистров, значения перечислений, права ролей. Основание — [Архитектура](Архитектура.md), п. 4, 9, 11 и [ТЗ](ТЗ.md).

**Документ машиночитаемый.** Генератор `tools/gen/generate.py` строит из него XML-выгрузку расширения (`src/cfe/`), которую Конфигуратор загружает командой «Загрузить расширение из файлов» или `/LoadConfigFromFiles`. Поэтому разделы 5–12 оформлены строго:

- заголовок объекта — `### <Вид>: <Имя>`; вид — одно из: `Перечисление`, `Справочник`, `ПланВидовХарактеристик`, `Документ`, `РегистрСведений`, `ОбщийМодуль`, `Роль`, `РегламентноеЗадание`, `Подсистема`;
- строка `Синоним: …` и строка `Свойства: ключ=значение; …` (необязательна);
- таблица реквизитов; табличная часть — заголовок `#### ТЧ: <Имя>` и своя таблица;
- синоним реквизита получается из имени («ДатаПубликации» → «Дата публикации»), если не задан в колонке «Синоним»;
- текст вне таблиц и строк `Синоним:`/`Свойства:` генератор не читает.

Меняете структуру → правите этот документ → запускаете генератор (п. 2.3). Правка XML вручную допустима только в том, чего генератор не создаёт (формы, модули, макеты).

## 2. Соглашения

### 2.1. Типы в таблицах

| Запись в спецификации | Тип 1С | В XML |
|---|---|---|
| `Строка(N)` / `Строка(0)` | Строка переменной длины, `0` — неограниченная | `xs:string` |
| `Число(N,M)`, `Число(N)` | Число, неотрицательное с суффиксом `+` (`Число(5)+`) | `xs:decimal` |
| `Булево` | Булево | `xs:boolean` |
| `Дата` / `ДатаВремя` | Дата (состав: дата / дата и время) | `xs:dateTime` |
| `ХранилищеЗначения` | ХранилищеЗначения | `v8:ValueStorage` |
| `ЛюбаяСсылка` | ЛюбаяСсылка | `cfg:AnyIBRef` (набор типов) |
| `СправочникСсылка.X`, `ДокументСсылка.X`, `ПеречислениеСсылка.X`, `ПВХСсылка.X` | Ссылки | `cfg:CatalogRef.X`, … |
| `Характеристика.X(Поле)` | Характеристика ПВХ со связью по типу с полем `Поле` того же объекта | `cfg:Characteristic.X` + `LinkByType` |
| `А \| Б` | Составной тип | несколько `v8:Type` |

Колонка **«Инд.»**: `И` — индексировать, `ИД` — индексировать с доп. упорядочиванием, пусто — нет.

### 2.2. Имена
- Все собственные объекты — с префиксом `кбп_`. Реквизиты — без префикса.
- Не используются имена стандартных реквизитов (`Родитель`, `Владелец`, `Код`, `Дата`, `Номер`, `НомерСтроки`, `Период`, `Регистратор`, `Активность`): процесс хранит `РодительскийПроцесс`, регистры — `НомерЗаписи`.
- Идентификаторы элементов схемы, переходов, кнопок и маркеров — `Строка(36)`. Для элементов графической схемы — `ид` + GUID без дефисов (34 символа): это `Имя` элемента схемы (Архитектура п. 5.1), а имя должно начинаться с буквы. У вариантов «Выбора варианта» своего имени нет: `ва` + MD5 от имени выбора и значения варианта.

### 2.3. Генерация, загрузка, выгрузка

Два каталога с разными ролями:

| Каталог | Что лежит | В git |
|---|---|---|
| `src/cfe/` | **Выгрузка Конфигуратора** (`DumpConfigToFiles -format Hierarchical`) — источник истины: формы, модули, всё, что сделано руками | да, байт в байт (CRLF, BOM — `.gitattributes`) |
| `build/cfe/` | Результат генератора — для загрузки в базу после изменения спецификации | нет |

Цикл изменения структуры:
```
1. правим docs/СпецификацияМетаданных.md
2. python3 tools/gen/generate.py                 # → build/cfe/
3. 1cv8 DESIGNER /F<база> /LoadConfigFromFiles build\cfe -Extension КонструкторБизнесПроцессов -files <изменённые файлы>
   (или частичная загрузка в Конфигураторе; полную загрузку делать только в пустое расширение — она заменит формы и модули)
4. 1cv8 DESIGNER /F<база> /DumpConfigToFiles src\cfe -Extension КонструкторБизнесПроцессов -format Hierarchical
5. коммит src/cfe/ вместе со спецификацией
```

- UUID объектов **детерминированы** (UUID v5 от полного имени объекта). Повторная генерация даёт те же UUID, и они совпадают с уже загруженными в базу — частичная загрузка не пересоздаёт объекты и не теряет данные.
- Генератор проверен сравнением с выгрузкой Конфигуратора: совпадает по содержанию. Различия только в оформлении — формат `2.21` против `2.20` (новые пустые `Caption`, `ShortCaption`, `Color` у значений перечислений), CRLF, порядок прав в ролях.
- **Заимствованный `Справочник.Пользователи`** — см. п. 4. Для загрузки в базу, где у `Пользователи` другой UUID: `--users-uuid <UUID>` (UUID — в `Catalogs/Пользователи.xml` выгрузки основной конфигурации) или `--adopted <каталог выгрузки расширения>`.
- **Зависимость от режима совместимости.** Длина номера строки табличных частей — 5 при режиме 8.3.26 и ниже, 9 — начиная с 8.3.27 (проверено загрузкой: при 9 Конфигуратор отказывает).
- **Формы генератор метаданных не создаёт.** Формы и обработки (`кбп_КонструкторСхем` с формой `УсловиеПерехода`, `кбп_МоиЗадачи`, формы элементов `кбп_Задачи`, `кбп_Процессы` и ПВХ `кбп_ПеременныеПроцессов`) собирает `tools/forms/build.py` прямо в `src/cfe/` (описание форм на Python, порядок тегов — по формам БСП). После загрузки в базу и выгрузки источником истины снова становится выгрузка Конфигуратора.
- Заготовки модулей (`Ext/Module.bsl`) и права ролей (`Ext/Rights.xml`) генератор пишет только в пустой каталог; `--force-modules` перезаписывает их.

## 4. Заимствованные объекты

| Объект | Зачем | Что заимствуется |
|---|---|---|
| `Справочник.Пользователи` | Исполнители, авторы, замещения | Только сам объект (для типа `СправочникСсылка.Пользователи`). Формы, реквизиты, модули — нет. |

**UUID заимствованного объекта и разные конфигурации.** В XML заимствованный объект хранит `ExtendedConfigurationObject` — UUID объекта основной конфигурации. У `Пользователи` он разный: в БСП 3.1 — `579baaa4-…`, в базе разработки — `fa1ef4b3-fc76-4b08-bb66-d89a7a1b66b1`. Это **не требует отдельного расширения под каждую конфигурацию**:

- у расширения выключено «Сохранять сопоставление с объектами расширяемой конфигурации по внутренним идентификаторам» (`KeepMappingToExtendedConfigurationObjectsByIDs = false`, п. 1). Такое расширение при подключении к базе сопоставляет заимствованные объекты **по именам**, UUID из XML для этого не используется;
- поэтому поставка одна — файл `.cfe`, собранный в базе разработки, подключается к ERP, КА, УТ, УНФ, БП как есть;
- UUID важен только при **загрузке XML** в Конфигуратор другой базы. Там он правится в один клик (свойства заимствованного объекта → сопоставить заново) или ключом генератора `--users-uuid`.

> **Проверить на этапе 0:** собрать `.cfe` в базе разработки («Конфигурация → Сохранить расширение в файл») и подключить его к базе БП и УНФ без правок. Если платформа откажет из-за UUID — вернуться к вопросу.

Заимствования из Архитектуры п. 3.1 (`ПодключаемыеКомандыПереопределяемый`, `ОбновлениеИнформационнойБазыПереопределяемый`, `УправлениеДоступомПереопределяемый`) добавляются на этапах 1 и 3 в Конфигураторе: общий модуль заимствуется вместе с методом, у которого появляется `&После`, и это удобнее сделать интерактивно.

---|---|---|
| `Справочник.Пользователи` | Исполнители, авторы, замещения | Только сам объект (для типа `СправочникСсылка.Пользователи`). Формы, реквизиты, модули — нет. |

Заимствования из Архитектуры п. 3.1 (`ПодключаемыеКомандыПереопределяемый`, `ОбновлениеИнформационнойБазыПереопределяемый`, `УправлениеДоступомПереопределяемый`) добавляются на этапах 1 и 3 в Конфигураторе: общий модуль заимствуется вместе с методом, у которого появляется `&После`, и это удобнее сделать интерактивно.

## 11. Роли

Права задаются по группам объектов. `Ч` — чтение и просмотр; `И` — чтение, добавление, изменение, удаление, интерактивные действия (без интерактивного удаления); `П` — `И` + проведение и отмена проведения (документы).

| Группа | Объекты |
|---|---|
| Дизайн | справочники `кбп_СхемыПроцессов`, `кбп_ВерсииСхем`, `кбп_ЭлементыСхем`, `кбп_РолиИсполнителей`, `кбп_ШаблоныСообщений`; ПВХ `кбп_ПеременныеПроцессов`; регистры `кбп_ПереходыСхем`, `кбп_КнопкиШагов`, `кбп_ИсполнителиШагов`, `кбп_ОповещенияШагов`, `кбп_ПараметрыСхем`, `кбп_ИсполнителиРолей`, `кбп_ПравилаЗапуска` |
| Справочные | справочник `кбп_ОбработчикиПроцессов` |
| Исполнение | справочники `кбп_Процессы`, `кбп_Задачи`; регистры `кбп_Маркеры`, `кбп_ЖурналПроцессов`, `кбп_ОчередьДействий`, `кбп_ОчередьОповещений` |
| Личные | регистры `кбп_УведомленияПользователей`, `кбп_ПодпискиПользователей` |
| Замещение | документ `кбп_Замещение`, регистр `кбп_Замещения` |
| Администрирование | регистр `кбп_Настройки` |
| Конструктор | обработка `кбп_КонструкторСхем` |
| Рабочее место | обработка `кбп_МоиЗадачи` |

Колонки: `| Роль | Дизайн | Справочные | Исполнение | Личные | Замещение | Администрирование | Конструктор | Рабочее место |`. Для обработок `Ч` и `И` — право «Использование» и «Просмотр».

### Роль: *
| Роль | Дизайн | Справочные | Исполнение | Личные | Замещение | Администрирование | Конструктор | Рабочее место |
|---|---|---|---|---|---|---|---|---|
| кбп_ИспользованиеПроцессов | Ч | Ч | И | И | Ч | Ч | | И |
| кбп_ДизайнПроцессов | И | Ч | Ч | И | Ч | Ч | И | И |
| кбп_РазработкаКодаПроцессов | | | | | | | | |
| кбп_АдминистрированиеПроцессов | И | И | И | И | П | И | И | И |
| кбп_НаблюдениеЗаПроцессами | Ч | Ч | Ч | И | Ч | Ч | | И |

- `кбп_ИспользованиеПроцессов` пишет в «Исполнение» потому, что движок работает в контексте пользователя. Строки процессов ограничиваются RLS (Архитектура п. 7) — ограничения добавляются на этапе 3, когда будет решено, через БСП или внутри API.
- `кбп_РазработкаКодаПроцессов` не даёт прав на объекты: наличие роли проверяется кодом (`РольДоступна`) при сохранении условий и обработчиков с произвольным кодом (этап 6).
- Всем ролям, кроме `кбп_РазработкаКодаПроцессов`, даётся право «Просмотр» подсистемы `кбп_БизнесПроцессы`.
- Роль `кбп_ДизайнПроцессов` сама по себе не даёт запуска процессов; методолог получает её вместе с `кбп_ИспользованиеПроцессов` в профиле групп доступа.
